# Research Report — Ancient Scripts AI

## Purpose

Documents the research report output, its structure, content rules, and how to extend it. The research report is the primary deliverable for researchers using the platform.

## When to Use

- When modifying `generate_markdown_report()` in `pipeline.py`.
- When changing how the export tab works in `ResultsDashboard.tsx`.
- When adding a new section to the report.
- When writing documentation about the report's scientific content.

## What the Research Report Is

The research report is a publication-ready Markdown document generated by `generate_markdown_report()` in `pipeline.py`. It is:
- Included in the API response as `research_report_markdown: str`.
- Displayed in the "Export Report" tab of `ResultsDashboard.tsx` inside a `<pre>` element.
- Downloadable by the researcher via a "Copy to Clipboard" button.

## Report Structure

The current report has 5 sections, plus a title block:

```markdown
# Computational Epigraphy & Decipherment Research Report
**Artifact Classification:** ...
**Chronological Horizon:** ...
**Provenance Group:** ...
**Analysis Date:** ...

---

## 1. Physical & Optical Observations (Level 1: Directly Observed)
- Image Resolution
- Focus / Sharpness (Laplacian Variance)
- Contrast Dynamics
- Surface Condition
- Candidate Grapheme Regions Detected

---

## 2. Machine Learning Predictions (Level 2: Predicted / Heuristic Demo)
- Top Script Prediction
- Reading Direction
- Model Framework

---

## 3. Epigraphic Corpus Cross-References (Level 3: Corpus Evidence)
- Sign Catalog Indexed
- Matched Sequence Patterns (with tablet references)
- Metrological System

---

## 4. Research Hypotheses & Semantic Interpretations (Level 4: Interpretations)
(One subsection per hypothesis, with rank, title, confidence, reconstructed reading,
supporting evidence list, uncertainties & limitations list)

---

## 5. Methodological Notes & Limitations
(Fixed notes about undeciphered status and prototype state)
```

## Content Rules

1. **Section 1** must contain only values from `image_quality` (real measurements). It must not include predicted values.
2. **Section 2** must explicitly label the model as demo: `"(Demonstration / Heuristic Weights)"`.
3. **Section 3** must state the corpus name and number of indexed entries.
4. **Section 4** must include for EVERY hypothesis: rank, title, confidence percentage, reconstructed reading in quotes, supporting evidence bullets, and uncertainties bullets.
5. **Section 5** must always state: (a) the script is undeciphered; (b) ML weights are demo placeholders.

## Writing Conventions for Reconstructed Readings

All reconstructed readings must use hedged language. Examples:

✅ Allowed:
- `"Belonging to the High Administrator ... allocation of livestock from the Central Domain: 2 Major Units, 4 Sub-allotments."`
- `"For the exalted shrine of the Deity [Divine Epithet], consecrated rations from the granary stores..."`

❌ Prohibited:
- `"This text says: The king commands..."`
- `"Translation: Give 2 units to the temple"`
- `"The inscription reads: ..."`

All non-translated portions must use square bracket notation: `[Title Holder]`, `[Divine Epithet]`, `[Toponym]` to indicate unknown proper nouns.

## Adding a New Section to the Report

1. Add the section to the f-string in `generate_markdown_report()`.
2. Only use variables already computed and passed as function arguments.
3. The section must follow the Level naming convention: `(Level N: ...)`.
4. Add the new section to the report structure table in this skill.
5. Test that the section renders correctly in the `<pre>` export tab.

## Export Improvements (Future)

- PDF export using `reportlab` or a headless browser.
- DOCX export using `python-docx`.
- Downloadable JSON export (full API response).
- BibTeX citation generator for corpus references.
- Direct export to institutional repositories.

## Definition of Done

- Report is non-empty for any valid image input.
- Report contains all 5 sections.
- Section 5 states the undeciphered status and prototype disclaimer.
- Reconstructed readings use hedged language and square brackets for unknown tokens.
- Report copies cleanly to clipboard from the Export tab.
